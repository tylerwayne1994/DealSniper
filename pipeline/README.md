# Deal Sniper — County Data Pipeline

Ingests **parcels** and **zoning** for the top-N US counties (by population) from
free/open data sources into Postgres 16 + PostGIS on an Oracle Cloud free-tier VM,
builds PMTiles per county per layer, and exposes bounded API routes to the app.

Key properties:
- **Nothing hardcoded** — every URL, threshold, model name, path and credential comes
  from `config/pipeline.yaml` + environment (`.env`, see `.env.example`).
- **Free data first** — per job the source ladder is walked in order:
  `bulk_download → arcgis_rest → socrata → ckan → statewide → scraper`.
  Scrapers are last-resort, robots-aware, rate-limited, and **held in
  `pending_approval` until you run `--approve`**.
- **Self-healing** — a job that fails after plain retries goes to Claude with full
  failure context; it can return a better free source, a rewritten adapter (run in a
  secrets-scrubbed sandbox before acceptance), or — only if no free data exists — a
  scraper (which still waits for approval). Hard cap: `selfheal.max_rewrites_per_job`
  API calls per job.
- **Idempotent** — re-running any ingest upserts (PK `fips,apn`; UNIQUE
  `jurisdiction_id,source_key`), never duplicates.
- **Bounded API** — the browser never receives a whole dataset; every route takes
  bbox+limit (env-capped) or a single-record key.

## Layout

```
pipeline/
  config/pipeline.yaml     all tunables; ${VAR} pulled from env, fail-fast when missing
  config/field_synonyms.yaml  header -> canonical field mapping per layer
  config/sources.yaml      GENERATED by discover — never hand-edit
  adapters/                one adapter per ladder rung + generated/ (self-heal output)
  core/                    discover, runner, validate, selfheal, join, tiles, db, registry
  api/routes.py            FastAPI router — mount into backend/App.py
  sql/001_schema.sql       schema (applied by run_migrations, tracked in schema_migrations)
  scripts/bootstrap_vm.sh  full VM provisioning
  scripts/run_all.sh       cron entry point
  tests/                   pytest suite (mocked; one live-DB test skips without DATABASE_URL)
```

## Setup (any machine)

```bash
cd pipeline
python3.12 -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env   # fill in DATABASE_URL / ANTHROPIC_API_KEY when needed
pytest
```

Commands and the env vars they require (missing ones are listed at startup):

| command | needs |
|---|---|
| `python -m core.discover` | the four public API bases |
| `python -m core.runner --dry-run ...` | nothing extra (reads sources.yaml) |
| `python -m core.runner ...` (real run) | `DATABASE_URL`, tiles vars, `ANTHROPIC_API_KEY`+`CLAUDE_MODEL` if self-heal on |
| `python -m core.runner --approve <target>/<layer>` | nothing |

## Discover

```bash
python -m core.discover                 # top 50 counties + jurisdictions + source per job
python -m core.discover --rediscover    # re-walk the ladder for every job (scraper jobs re-check rungs 1–5)
python -m core.discover --limit 3       # debugging: top 3 counties only
```

Prints the **rung histogram** (jobs per rung, per layer) so you can see how many jobs
run on free data vs scrapers. Jobs no rung satisfies are flagged `discovery_mode` and
go to self-heal (with web search) on the next real run.

Notes:
- Zoning is jurisdiction-level: one job per incorporated place plus `<fips>-UNINC` for
  the county's unincorporated area. CDPs are recorded in `jurisdictions` but get no
  zoning job — they have no zoning authority; county zoning covers them.
- Discover is incremental: resolved jobs are kept unless `--rediscover`.

## Run

```bash
python -m core.runner --county 06037 --layer parcels --dry-run   # fetch + validate, no writes
python -m core.runner --county 06037                             # full ingest + join + tiles
python -m core.runner                                            # everything, by county rank
python -m core.runner --approve 12086-UNINC/zoning               # release a scraper
python -m core.runner --no-selfheal                              # disable Claude escalation
```

Every attempt is recorded in `ingest_runs` with full error context. The end-of-run
report (printed + `reports/<timestamp>.md`) lists per-job status/rung/rows/duration,
scraper-rung jobs with the reasons rungs 1–5 failed, `pending_approval` scrapers,
`needs_human` jobs, and unmapped zoning codes (extend `zone_categories` in config).

## VM provisioning (Oracle Cloud always-free)

1. Create a `VM.Standard.A1.Flex` instance (4 OCPU / 24 GB), Ubuntu 22.04+, 200 GB
   block volume mounted (put `TILES_DIR` and the Postgres data dir on it).
2. **OCI console (can't be scripted from the VM):** VCN → subnet → security list →
   add ingress rules for TCP 80/443 (tiles; open) and TCP 6432 (PgBouncer; restrict
   source CIDR to your app's egress IPs). Also `sudo ufw allow 80,443,6432/tcp` if ufw
   is enabled.
3. Clone the repo, `cd pipeline`, create `.env` from `.env.example` (real
   `DATABASE_URL`, `TILES_DIR=/srv/tiles`, `TILES_BASE_URL=https://<vm-host>/tiles`,
   `NGINX_CORS_ORIGIN=<app origin>`, `ANTHROPIC_API_KEY`, contactable
   `SCRAPER_USER_AGENT`).
4. `set -a; . .env; set +a; bash scripts/bootstrap_vm.sh`
5. `source .venv/bin/activate && python -m core.discover && python -m core.runner`

Cron: `run_all.sh` is installed at `schedule.cron` (default Sunday 03:00) — it
re-uses `sources.yaml` and upserts everything.

## App integration

- **API**: mount the router in `backend/App.py`:
  ```python
  from pipeline.api.routes import router as parcels_router
  app.include_router(parcels_router)
  ```
  Point `DATABASE_URL` at PgBouncer (`postgresql://user:pass@<vm-host>:6432/dealsniper`)
  and set `PARCEL_API_DEFAULT_LIMIT` / `PARCEL_API_MAX_LIMIT`.
  Routes: `GET /api/parcels?bbox=&limit=`, `GET /api/parcels/{fips}/{apn}`,
  `GET /api/zoning?bbox=&limit=`, `GET /api/zoning/at?lat=&lon=`, `GET /api/coverage`.
- **Map**: load `<TILES_BASE_URL>/index.json`, add PMTiles sources
  (`<fips>_parcels.pmtiles`, `<fips>_zoning.pmtiles`) only for in-view counties.

## Acceptance tests (§13) — where each runs

| # | test | where |
|---|---|---|
| 1 | `pytest` (mocked adapters, validator, self-heal safety, approval gating) | anywhere |
| 2 | `python -m core.discover` → sources.yaml + rung histogram | anywhere (network) |
| 3 | `--dry-run` fetch ≥ min_rows | anywhere (network) |
| 4 | full county end-to-end + tiles + API < 1 s | VM (needs PostGIS + tippecanoe) |
| 5 | break a source URL → self-heal climbs/rewrites/`needs_human`, ≤ max_rewrites calls | VM (needs `ANTHROPIC_API_KEY`) |

Test 5 procedure: edit the `sources` row for one county (`UPDATE sources SET
source_url = source_url || 'BROKEN' WHERE target_id='<fips>' AND layer='parcels'`),
run `python -m core.runner --county <fips> --layer parcels`, then check
`ingest_runs` + the report: the job must end `ok` (new source/adapter) or
`needs_human`, with `rewrite_count <= selfheal.max_rewrites_per_job`.
